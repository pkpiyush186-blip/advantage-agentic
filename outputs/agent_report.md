# Agentic Process - End-to-End Results

Generated by `scripts/04_run_agent.py`. All 26 weekly cycles were driven through the LangGraph graph, with a simulated manager answering approvals. No LLM call and no API key were involved in any decision.

## 1. Outcome

| Strategy | Conversions | Conv. per lakh | vs As-Is |
|---|---:|---:|---:|
| As-Is monthly manual | 43,528 | 145.58 | - |
| Allocator alone (phase 2) | 47,450 | 158.70 | +9.0% |
| **Full agentic process** | **47,341** | **158.33** | **+8.8%** |
| Oracle (ceiling) | 49,043 | 164.02 | +12.7% |

The full process gains **+8.8%** against the As-Is baseline.

That is 0.2 pp below the allocator running on its own (phase 2). The difference is **the cost of governance**: frozen channels during anomalies, halved shift caps on degraded data, manager overrides and held weeks all pull the allocation away from what the allocator would have chosen. Governance is not free, and showing its price is more useful than hiding it.

## 3. Exception paths exercised

| Path | What it does | Cycles |
|---|---|---:|
| E1 | Freeze the affected channel, re-plan across the rest, escalate | 2 |
| E2 | Fall back to last valid data, mark degraded, halve the shift cap | 1 |
| E3 | Trim and re-check; escalate if nothing complies | 0 |
| E4 | Log the override, re-plan with it as a constraint, re-run S3-S5 | 2 |
| E5 | Reminder, escalate to the senior approver, hold the allocation | 1 |

E1 and E2 fire from the shocks built into the world (weeks 8, 14, 17). E4 and E5 are driven by the scripted manager scenario so they are reproducible for the demonstration. E3 fires whenever the guardrail cannot find a compliant split.
